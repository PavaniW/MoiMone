SMS & WhatsApp run steps 1→6. Manual web entry skips parsing (the form is already structured) and goes straight to insert + balance; edits/deletes use reverse-old → apply-new so balances never drift.

Transaction model — three types only

There is no separate “savings” type. A saving is a transfer tagged with a goal.

expensemoney spentcard_id (from)—yesyes

All amounts stored in LKR. Accounts live in one cards table typed credit · debit · cash · bank, each with a balance — “cards” and “accounts” are the same thing. Transfers never carry payment_method/card_last4; income/expense never carry a goal.

Account linking — precedence

  • 1. exact card by last-4 (real bank SMS)
  • 2. cash → your Cash account
  • 3. named card type (“from debit card”) → your sole account of that type
  • 4. transfers → match from/to by account name

Left unlinked only when ambiguous (e.g. two debit accounts, no last-4).

Balance & goal maintenance

  • expense lowers · income raises · transfer moves from−/to+ (net-zero if internal)
  • SMS stating an available balance = authoritative (sets it directly)
  • goal-tagged transfer also adds to goal progress
  • edit/delete = reverse-old → apply-new (no drift)

Reads — looking at your money

Dashboard

  • Income / Spent / Saved — monthly flows
  • Available — live balance (debit + cash)
  • By category · by account · 6-month trend

Other reads

  • Transactions net = income − expense − goal-transfers
  • Budgets — spend vs. each category’s own limit
  • Chat — LLM gets availableNow (debit+cash), per-account balances, month flows, budgets, goals; answers from those exact figures

Multi-user, environments & security

Scoping

  • Own Google account each → Supabase Auth (JWT)
  • Every row has space_id + created_by
  • Scoped in code: ledgers by space_id ∈ your spaces, accounts by user_id
  • Personal space private; optional shared “household” space

Environments & secrets

  • Local — Express :3000, parser = Ollama, web :5173
  • Prod — Vercel (web + Express same-origin), parser = Groq
  • Both → same Supabase (shared data)
  • service-role key backend-only; webhooks authed (token / Twilio sig)
